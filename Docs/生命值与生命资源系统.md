# 生命值与生命资源系统

> 当前实现文档，整理日期：2026-07-29。后续功能应以本文和对应代码为基础继续扩展。

## 1. 系统目标

当前系统由四部分组成：

1. 玩家现有生命值系统 `Health`。
2. 玩家生命储备 `PlayerHealthReserve`。
3. 可被玩家攻击并产出生命储备的生命资源节点 `HealthResourceNode`。
4. 生命资源 Prefab 的制作、索引及关卡编辑器布置流程。

核心玩法流程：

`玩家攻击资源节点 → 节点耐久归零 → 奖励自动写入生命储备 → 玩家受伤后按 G 施放恢复技能 → 在技能生效点恢复生命`

生命资源只用于回血，目前不包含背包、货币、多人归属或其他资源类型。

## 2. 运行时逻辑

### 2.1 玩家生命值

玩家沿用项目已有的 `Platformer.Mechanics.Health`：

- `CurrentHP`：当前生命值。
- `maxHP`：最大生命值。
- `Heal(amount)`：恢复生命并返回实际恢复量。
- `RestoreFull()`：恢复至满血。
- `IsAlive`：玩家是否存活。

生命储备容量始终动态等于玩家 `maxHP`，不另设独立容量配置。

### 2.2 生命储备

组件：`PlayerHealthReserve`

- `Current`：当前储备量。
- `Capacity`：储备上限，即玩家最大生命值。
- `Add(amount)`：写入储备，超过上限的部分直接溢出并浪费。
- `Changed(current, capacity)`：储备变化事件，供 UI 等系统监听。
- `Clear()`：清空储备。
- `TryReserveForFullHeal(out amount)`：准备一次恢复时，按“玩家缺失生命”和“现有储备”中的较小值预扣。

示例：玩家最大生命为 5、当前生命为 2、储备为 2，按 G 后预扣 2，技能成功结算后玩家恢复到 4。

满血、死亡、没有储备或已经在施法时，不能开始恢复；满血按 G 不消耗储备。

### 2.3 G 恢复技能

组件：`PlayerRecoveryAbility`

当前默认参数：

- 输入：`PlayerInputReader.RecoverPressed`（当前设计为 G）。
- 施法时间：`0.8` 秒。
- 生效点：施法进度的 `65%`。
- 动画：可在 `recoveryClip` 配置恢复动画。

执行顺序：

1. 检查玩家存活、确实缺血、拥有储备、未在重复施法，且技能系统不忙。
2. 开始施法前先从储备中预扣本次可恢复量。
3. 锁定玩家移动并进入 `Cast` 动画状态。
4. 到达指定生效点后调用 `Health.Heal(reservedAmount)`。
5. 播放完毕后解除移动锁定和强制动画状态。

恢复也可由动画事件调用公开方法 `CommitHeal()`，以便将回血准确对齐到动画帧。

打断规则：调用 `CancelCurrentAction(...)` 会终止施法；本次已经预扣的储备不会返还，也不会回血。这与当前设计“被打断并消耗储备”一致。

### 2.4 生命周期与跨场景规则

- 从 Reality 进入对应 Mirror：玩家对象和生命储备随持久玩家保留。
- 返回 Reality：清空生命储备，并将玩家恢复至满血。
- 玩家死亡并在当前 Reality 复活：清空生命储备。
- 重新进入 Reality 或进入下一现实关卡：清空生命储备；关卡流程按满血重新开始。
- 资源节点自身的摧毁状态不保存：当前关卡运行期间不会重生，重新加载/进入关卡后随场景重新出现。

相关事件为 `MirrorTransitionBridge.OnReturnToRealityScene` 和 `PlayerDamageReceiver.PlayerRespawned`。

## 3. 生命资源节点

组件：`HealthResourceNode`，Prefab 根节点必须同时拥有 `Collider2D` 和 `Hurtbox`。

### 3.1 伤害判定

攻击通过 `Hurtbox.ReceiveHit(DamagePayload)` 向上发送到资源节点。

只有 `DamagePayload.source` 的父级中存在 `PlayerInputReader` 时才视为玩家攻击。敌人、环境、陷阱等非玩家来源不会扣除节点耐久，也不会产生奖励。

节点有两种耐久计算模式：

- 默认：按 `payload.damage` 扣除耐久。
- `countHitsInsteadOfDamage = true`：每次有效攻击固定扣 1 点耐久。

### 3.2 可配置字段

- `maxDurability`：节点最大耐久。
- `healthReward`：摧毁后尝试写入的固定生命储备量。
- `countHitsInsteadOfDamage`：按命中次数而非伤害值计算。
- `animator` / `hitTrigger`：受击动画。
- `flashRenderers` / `flashColor` / `flashDuration`：受击材质闪烁。
- `hitSound` / `hitVolume`：受击音效。
- `rewardOrbSprite` / `rewardOrbColor` / `rewardTravelDuration`：奖励飞向玩家的表现。
- `keepDepletedVisual`：耗尽后是否保留外观。
- `deactivateDelay`：不保留外观时的延迟隐藏时间。

### 3.3 摧毁和奖励

耐久归零后：

1. 立即将固定奖励写入攻击者的 `PlayerHealthReserve`；找不到攻击者储备时会兜底查找场景中的玩家储备。
2. 奖励飞行动画仅是视觉表现，储备在节点摧毁时已经到账，切场景或特效丢失不会吞掉奖励。
3. 禁用节点 `Hurtbox` 和 `Collider2D`，避免重复受击和重复奖励。
4. 触发 `Depleted` 事件。
5. 默认延迟后隐藏整个节点，不播放额外摧毁动画或音效。

## 4. UI 系统

### 4.1 运行时绑定

玩家组件 `PlayerHealthBarUI` 同时监听生命值、生命储备和恢复技能状态，并驱动 `PlayerHealthBarView`：

- `SetHealth(currentHP, maxHP)` 更新当前血量。
- `SetReserve(current, capacity)` 更新细长生命储能条。
- `SetCasting(isCasting)` 显示恢复技能施法状态。

生命条与储能条制作在同一个 HUD Prefab 中并贴合显示，不使用中间粉色分隔。

### 4.2 当前 Prefab 与关卡绑定

- 默认兜底：`Assets/MirrorTrial/Resources/UI/PlayerHealthBarUI.prefab`
- Reality_01：`Assets/MirrorTrial/Resources/UI/PlayerHealthBarUI_Reality01.prefab`
- Reality_02：`Assets/MirrorTrial/Resources/UI/PlayerHealthBarUI_Reality02.prefab`

每个 `LevelConfig.playerHealthHudPrefab` 决定该关卡使用哪个 HUD。`LevelManager.Awake()` 将关卡配置的 HUD 交给 `PlayerHealthBarUI`；没有配置时才从 `Resources/UI/PlayerHealthBarUI` 加载默认版本。

Reality_02 当前已绑定自己的 `PlayerHealthBarUI_Reality02.prefab`。

## 5. 资源 Prefab 管理

### 5.1 生命资源编辑器

入口：Unity 顶部菜单 `Tools → Mirror Trial → 关卡 → 生命资源编辑器`。

该工具用于选中单个美术 Prefab 后配置：耐久、固定奖励、受击动画 Trigger、闪烁和受击音效。应用配置时会保证 Prefab 具备 `HealthResourceNode`，随后验证 `Collider2D`、`Hurtbox` 和资源节点组件，并自动注册到资源目录。

当前不要求多选或批量配置；操作方式是选中一个、配置并注册，再选择下一个。

### 5.2 Prefab 仓库索引

索引资产：`Assets/MirrorTrial/Resources/HealthResourceCatalog.asset`

类型：`HealthResourceCatalog`，内部保存生命资源 Prefab 的直接引用列表。关卡编辑器读取该资产，而不是自己扫描或手工维护另一套列表。

索引更新方式：

- 生命资源编辑器应用配置后调用 `Register(prefab)` 自动加入目录并去重。
- 关卡编辑器点击“刷新索引”时调用 `Rebuild()`，扫描项目内所有带 `HealthResourceNode` 的 Prefab，排序、去重并重建目录。
- 目录为空时，关卡编辑器首次启用会自动重建。

因此，任何符合条件的生命资源 Prefab 都能通过统一引用关系进入仓库。

### 5.3 关卡编辑器布置

入口：`Tools → 镜像试炼 → 关卡编辑器`。

使用方式：

1. 打开包含 `LevelManager` 的目标关卡。
2. 在关卡编辑器切换到“玩法”页签。
3. 在“生命资源仓库”中点击目标 Prefab 卡片。
4. 点击开启放置。
5. 在 Scene 视图中左键点击一次，生成一个 Prefab 实例。

实例会放入当前关卡 `GameplayRoot/HealthResources` 下，保留与源 Prefab 的关联，支持 Undo，并在放置后自动选中新对象。每次开启放置只生成一个实例，需要继续布置时再次开启。

当前仓库包含示例资源及两种生命植物 Prefab，具体内容以 `HealthResourceCatalog.asset` 为准。

## 7. 后续扩展建议与约束

后续增加功能时，建议保持以下职责边界：

- `Health` 只管理玩家实际生命值。
- `PlayerHealthReserve` 只管理储备数据、容量和生命周期，不直接处理输入或动画。
- `PlayerRecoveryAbility` 负责消耗储备、施法、打断和回血结算。
- `HealthResourceNode` 负责可攻击资源的耐久、反馈和奖励产出。
- `HealthResourceCatalog` 是关卡编辑器选择 Prefab 的唯一索引来源。
- `PlayerHealthBarView` 只负责显示，避免将玩法规则写进 UI。

适合直接扩展的接口：

- 监听 `PlayerHealthReserve.Changed` 添加新 UI、音效或提示。
- 监听 `HealthResourceNode.DurabilityChanged` 添加耐久条或阶段表现。
- 监听 `HealthResourceNode.Depleted` 添加消散、粒子或关卡事件。
- 监听 `PlayerRecoveryAbility.CastStateChanged` 添加施法条、特效或输入提示。
- 新增不同美术 Prefab 时，继续复用 `HealthResourceNode` 并注册到同一个目录。

当前已知设计约束：奖励为固定整数；储备上限等于最大生命；恢复开始时预扣且打断不返还；资源状态不存档；仅玩家攻击有效；单玩家环境。

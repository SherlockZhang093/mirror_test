# 《破映》镜前准备与工具卡机制 PRD

**文档版本：** V1.0  
**更新日期：** 2026-08-13  
**适用范围：** Mirror Trial Demo  
**文档状态：** 方案评审稿  

---

## 1. 需求概述

目前玩家每次进入 Mirror 前，会进入一次三选一的成长选择。现有选项以最大生命、攻击伤害、移动速度等属性成长为主，选择结果会立即作用于当前会话中的玩家。

本需求希望在同一选择流程中加入“工具卡”：玩家可以放弃长期属性成长，改为携带一个只服务于下一次 Mirror 挑战的战术工具。工具卡不扩展为传统卡组、背包或装备系统，而是作为镜前准备的一部分，为 Boss 战提供一次明确的战术选择。

### 1.1 一句话定位

**玩家在进入 Mirror 前，从属性成长与战术工具中选择一项，以决定本次挑战是强化自身，还是获得一次主动破局手段。**

### 1.2 核心设计判断

该机制可在现有系统基础上实现，且与当前“进入 Mirror 前进行选择”的流程高度契合。V1 应复用现有三选一界面、生命精华消费和流程暂停能力，但必须将“属性成长”和“工具装备”拆分为两套效果逻辑，避免把工具继续塞入属性枚举中。

---

## 2. 设计目标

### 2.1 核心目标

1. 增加镜前决策的策略性，使玩家不再只比较数值大小。
2. 让不同 Boss、不同玩家状态产生不同的最优选择。
3. 为处于劣势的玩家提供有限但可感知的破局手段。
4. 复用现有生命精华，使关卡探索资源与 Mirror 战斗准备形成闭环。
5. 在不引入完整背包、卡组和复杂装备栏的前提下，验证工具玩法是否有趣。

### 2.2 体验目标

- 属性卡代表“稳定、长期、低操作门槛”的收益。
- 工具卡代表“短期、针对性、需要判断时机”的收益。
- 玩家看到 Boss 或关卡特征后，能够产生“这一局我想带这个”的明确理由。
- 工具使用后必须有强反馈，玩家能够立刻理解工具是否生效。

### 2.3 非目标

V1 不包含以下内容：

- 卡组、抽牌、弃牌、手牌和牌库构筑。
- 多格背包、道具堆叠和自由整理。
- 工具合成、升级、稀有度和随机词条。
- 局内掉落新的工具卡。
- 同时携带多个工具。
- 永久解锁树和跨存档收集。
- 工具之间的复杂组合技。

## 3. 名词定义

| 名词 | 定义 |
|---|---|
| 镜前准备 | 玩家击碎镜门后、正式加载 Mirror 场景前出现的选择流程。 |
| 准备卡 | 镜前准备界面中的通用选项，分为属性卡和工具卡。 |
| 属性卡 | 购买后立即提升玩家属性，并在当前游戏会话内持续生效。 |
| 工具卡 | 购买后装备一个战术工具，仅在下一次 Mirror 挑战中可用。 |
| 工具槽 | 玩家唯一的工具装备位置，V1 同时最多装备一个工具。 |
| 工具次数 | 当前工具在一次 Mirror 挑战中可以成功触发的次数。 |
| Mirror 挑战 | 从玩家进入 Mirror 场景开始，到 Boss 胜利或玩家死亡离开 Mirror 为止。 |

## 4. 核心玩法规则

### 4.1 镜前选择规则

1. 玩家击碎镜门后，打开“镜前准备”界面。
2. 界面展示三张准备卡。
3. V1 默认配置为：**两张属性卡 + 一张工具卡**。
4. 玩家最多选择一张，也可以跳过并保留生命精华。
5. 选择成功后立即扣除对应生命精华。
6. 属性卡立即生效；工具卡进入工具槽。
7. 完成选择或跳过后，关闭界面并继续进入 Mirror。

### 4.2 为什么采用“两属性 + 一工具”

- 每次都能看到工具，便于稳定验证工具机制。
- 保留现有属性成长的主体地位，不会突然改变 Demo 的成长结构。
- 避免三张纯随机卡导致某次完全没有工具，玩家无法形成预期。
- 避免三张工具卡同时出现，使早期内容量和美术需求迅速膨胀。

后续若工具数量和 Boss 数量充足，可以改为从统一卡池按权重生成，但不属于 V1。

### 4.3 选择互斥

属性卡和工具卡占用同一次选择机会。玩家选择工具卡后，本次不能再购买属性卡；选择属性卡后，本次不能再装备工具。

这一互斥关系是本机制的核心。如果允许每次同时拿属性和工具，工具将退化为固定赠品，无法形成有意义的取舍。

### 4.4 属性卡规则

- 沿用现有最大生命、攻击伤害、移动速度等效果。
- 购买后立即生效。
- 在当前 Demo 会话内持续保留。
- 进入或离开 Mirror 不会清除。
- 开始新游戏或重置会话时清除。

### 4.5 工具卡规则

- 选择后装备到唯一工具槽。
- 工具只在紧接着进入的 Mirror 挑战中可用。
- 工具拥有固定使用次数，V1 不支持补充次数。
- 工具成功生效后才扣除一次使用次数。
- 工具次数耗尽后，工具槽进入“已耗尽”状态，但图标保留至本次挑战结束。
- Boss 胜利、玩家死亡离开 Mirror、返回主菜单或开始新游戏时，清空工具槽。
- 未使用的次数不能带回现实关卡，也不能带入下一面镜子。

### 4.6 死亡与重试规则

V1 将每次进入 Mirror 视为一次独立挑战：

- 玩家死亡离开 Mirror 后，当前工具及剩余次数全部清除。
- 玩家再次击碎或进入该镜门时，重新出现镜前准备。
- 再次选择工具需要重新支付生命精华。
- 属性成长仍按当前系统规则保留。

该规则实现简单、认知清晰，也能让工具成本与每次挑战绑定。测试阶段需要重点关注重复失败是否导致资源压力过高；若挫败感明显，后续可改为“同一镜门首次购买后，重试免费恢复工具”。

## 5. 玩家流程

### 5.1 标准流程

1. 玩家在现实关卡探索并获得生命精华。
2. 玩家到达镜门并完成击碎动作。
3. 游戏暂停玩家操作，展示镜前准备界面。
4. 玩家查看三张准备卡：两张属性卡、一张工具卡。
5. 玩家比较长期成长与本次战术收益。
6. 玩家选择一张卡，或选择跳过。
7. 系统校验余额和效果是否可用。
8. 校验成功后扣除生命精华并应用选择。
9. 界面显示短暂的选择结果反馈。
10. 界面关闭，玩家进入 Mirror。
11. 若装备了工具，Mirror HUD 显示工具图标、按键和剩余次数。
12. 玩家在战斗中按工具键使用工具。
13. Boss 胜利或玩家死亡后，清空工具状态。

### 5.2 失败分支

- **精华不足：** 卡牌置灰，不允许点击，显示“生命精华不足”。
- **工具与当前场景不兼容：** 工具卡不进入候选池；若配置错误仍出现，则置灰并记录错误。
- **工具目标条件不满足：** 不触发效果、不扣次数，并给出轻量提示。
- **连续点击：** 第一次有效选择后立即锁定全部卡牌，避免重复消费。
- **界面异常销毁：** 恢复时间、输入和鼠标状态，并继续原有进入 Mirror 流程。

## 6. 工具操作规则

### 6.1 输入

- 新增独立“使用工具”动作。
- 键鼠默认按键建议为 **R**，但必须允许通过输入配置调整。
- 工具使用不能复用攻击、闪避、恢复或交互按键，避免战斗中误触。
- 当玩家输入被锁定、处于死亡状态或剧情演出中时，禁止使用工具。

### 6.2 通用使用条件

使用工具前，系统依次检查：

1. 当前是否处于 Mirror 场景。
2. 是否装备工具。
3. 剩余次数是否大于 0。
4. 是否处于工具冷却或公共使用间隔中。
5. 玩家当前状态是否允许使用。
6. 工具自身目标条件是否满足。

全部通过后执行工具效果。只有效果确认成功后才消耗次数。

### 6.3 动作优先级

- V1 工具不打断死亡、受击硬直、倒地、剧情和场景切换。
- 工具默认允许在移动、跳跃和普通待机状态中使用。
- 是否打断攻击由具体工具决定；首批工具建议均不打断攻击，以降低动作系统接入风险。
- 同一帧多次输入只接受一次。

## 7. V1 工具卡设计

首版建议制作三种工具，分别覆盖生存、容错和进攻窗口，且尽量复用现有战斗能力。

### 7.1 回生瓶

| 字段 | 配置建议 |
|---|---|
| 定位 | 主动恢复，降低低血量进入 Boss 战的压力 |
| 消耗 | 5 点生命精华 |
| 使用次数 | 1 次 |
| 效果 | 恢复 2 点当前生命，不突破最大生命 |
| 使用限制 | 满生命时不可使用，不消耗次数 |
| 反馈 | 青绿色闪光、生命槽回填、清晰恢复音效 |

设计价值：最容易理解，适合作为工具系统教学卡，也是技术风险最低的首个工具。

### 7.2 镜盾

| 字段 | 配置建议 |
|---|---|
| 定位 | 主动防御，为不熟悉 Boss 招式的玩家提供容错 |
| 消耗 | 6 点生命精华 |
| 使用次数 | 1 次 |
| 效果 | 使用后 2 秒内抵消下一次有效伤害，触发后立即结束 |
| 使用限制 | 已处于镜盾保护状态时不可重复使用 |
| 反馈 | 玩家周身出现镜面护罩；成功格挡时碎裂、闪白并播放清脆反馈 |

设计价值：不会直接跳过 Boss 机制，但能显著缓解一次判断失误。

### 7.3 定影钉

| 字段 | 配置建议 |
|---|---|
| 定位 | 主动控制，创造输出或恢复窗口 |
| 消耗 | 7 点生命精华 |
| 使用次数 | 1 次 |
| 效果 | 使 Boss 的移动与动作速度降低 40%，持续 3 秒 |
| 使用限制 | Boss 无敌、转阶段或剧情演出期间不可使用 |
| 反馈 | Boss 脚下生成钉影与镜面波纹，轮廓变冷色，结束前逐渐恢复正常 |

设计价值：提供明显战术差异，但需要统一处理 Boss 阶段切换和时间缩放，技术风险高于前两项。

### 7.4 首版实施顺序建议

1. 回生瓶。
2. 镜盾。
3. 定影钉。

如果只制作一个最小可玩版本，优先完成回生瓶，并用它验证选择、装备、HUD、输入、消耗和清空的完整闭环。

## 8. 卡牌展示设计

### 8.1 界面命名调整

现有界面建议从“关末成长”改名为 **“镜前准备”**，避免工具卡加入后名称仍暗示只有属性成长，也更符合当前实际触发位置。

### 8.2 卡牌信息层级

每张准备卡至少展示：

1. 卡牌类型标签：属性 / 工具。
2. 名称。
3. 核心数值或使用次数。
4. 一句话效果说明。
5. 生命精华消耗。
6. 不可选择原因。

### 8.3 类型区分

- 属性卡使用稳定、明亮的成长色系。
- 工具卡使用更偏战术、器物感的色系和边框。
- 不能只依赖颜色区分，必须同时显示“属性”或“工具”文字标签。
- 工具卡核心数值优先展示“1 次”，而不是把所有描述塞入正文。

### 8.4 选择反馈

- 选择属性卡：显示“已获得：攻击伤害 +2”等即时结果。
- 选择工具卡：显示“已装备：镜盾 ×1”。
- 工具卡选择后可播放工具进入槽位的短动画。
- 反馈结束后再继续场景切换，时长建议 0.5 至 0.8 秒。

## 9. Mirror 内工具 HUD

### 9.1 显示内容

进入 Mirror 且装备工具时，HUD 显示：

- 工具图标。
- 默认按键提示。
- 剩余次数。
- 不可使用状态或冷却遮罩。

未装备工具时不显示空工具栏，避免增加无意义界面负担。

### 9.2 状态表现

| 状态 | HUD 表现 |
|---|---|
| 可使用 | 图标正常显示，按键提示清晰 |
| 暂不可用 | 图标降低亮度，显示轻量原因或禁用反馈 |
| 成功使用 | 次数立刻减少，图标播放确认动画 |
| 次数耗尽 | 图标灰化并显示 0，不立即消失 |
| 离开 Mirror | 整个工具 HUD 隐藏并清空 |

## 10. 卡池与配置规则

### 10.1 V1 出牌方式

V1 不做完全随机卡池，由每个镜门配置自己的候选内容：

- 两张属性卡可以沿用当前固定配置。
- 一张工具卡由镜门或对应 Boss 配置指定。
- 同一个工具可以出现在多个镜门前。
- 工具必须与目标 Boss 兼容，不能出现完全无效的选择。

这样可以让策划明确控制每一场 Boss 战的教学与难度，同时避免早期随机系统掩盖工具本身的问题。

### 10.2 后续扩展方向

当工具数量达到 6 个以上、Mirror 数量达到 4 个以上时，再评估：

- 按 Boss 标签筛选工具。
- 属性与工具按权重随机。
- 保底至少出现一张工具卡。
- 已购买卡牌的重复出现限制。
- 卡牌刷新和额外付费。

以上均不进入 V1 验收范围。

## 11. 系统职责划分

### 11.1 镜前准备系统负责

- 获取并展示三张准备卡。
- 展示类型、消耗、效果和不可用原因。
- 查询生命精华余额。
- 校验是否能够选择。
- 执行一次消费。
- 将属性卡交给属性成长系统。
- 将工具卡交给工具装备系统。
- 限制一次准备最多选择一张。
- 选择完成后继续进入 Mirror。

### 11.2 工具装备系统负责

- 保存当前装备的工具和剩余次数。
- 响应使用工具输入。
- 校验通用使用条件。
- 调用具体工具效果。
- 成功后扣除次数。
- 向 HUD 广播状态变化。
- 在 Mirror 挑战结束时清空状态。

### 11.3 具体工具效果负责

- 判断自身目标条件。
- 执行效果。
- 返回是否成功生效。
- 触发对应视效、音效和镜头反馈。

### 11.4 系统不应负责

- 准备卡定义不保存玩家运行时次数。
- UI 不直接修改玩家生命、伤害或 Boss 状态。
- 工具效果不直接控制场景切换。
- 属性成长系统不处理工具装备与消耗。

## 12. 数据结构需求

### 12.1 通用准备卡定义

所有卡牌共享以下配置：

- 唯一 ID。
- 卡牌类型。
- 显示名称。
- 图标。
- 简短描述。
- 生命精华消耗。
- 卡牌类型标签。
- 是否允许跳过。

### 12.2 属性卡定义

- 属性效果类型。
- 提升数值。
- 数值格式。
- 对应的属性应用逻辑。

### 12.3 工具卡定义

- 工具类型。
- 初始使用次数。
- 冷却或公共使用间隔。
- 使用条件。
- 工具效果参数。
- HUD 图标。
- 使用音效。
- 使用视效。
- 可用 Boss 或场景标签。

### 12.4 运行时工具状态

运行时状态至少包含：

- 当前工具 ID。
- 剩余次数。
- 是否可使用。
- 冷却结束时间。
- 所属 Mirror 挑战标识。

运行时状态必须保存在玩家或会话对象上，不能写回共享的卡牌配置资源。

## 13. 与现有系统的关系

### 13.1 可直接复用

- 击碎镜门后、进入 Mirror 前的触发点。
- 打开界面时暂停时间和玩家输入。
- 三张卡牌的容器和选择交互。
- 生命精华余额、消费接口和余额刷新。
- 一次只能选择一张的防重复逻辑。
- 跳过并保留精华。
- 选择结束后继续场景切换。
- 持久玩家跨场景存在的能力。

### 13.2 需要调整

- “关末成长”命名调整为“镜前准备”。
- 卡牌界面从只识别属性卡，调整为识别通用准备卡。
- 卡牌数据从单一属性定义拆分为属性定义和工具定义。
- 选择结果从固定调用属性应用器，改为按卡牌类型分发。
- 新增工具槽、工具输入和工具 HUD。
- 新增 Mirror 结束时的工具清理逻辑。

### 13.3 明确禁止的实现方式

- 不把回生瓶、镜盾等继续加入属性效果枚举。
- 不让卡牌 UI 直接查找 Boss 并修改其状态。
- 不把剩余次数保存在工具卡配置资源中。
- 不通过复制三套独立面板来分别处理属性卡和工具卡。

## 14. 平衡原则

### 14.1 属性卡与工具卡价值

工具卡是一次挑战内的强战术效果，属性卡是当前会话内的持续收益。两者不需要在单场战斗内绝对等值，但必须让玩家存在合理犹豫。

建议采用以下价值关系：

- 前期：工具卡略强，帮助玩家理解和愿意尝试系统。
- 中后期：属性成长通过累计逐渐获得长期优势。
- 工具价格可以接近或略高于同阶段属性卡。
- 工具不能直接秒杀 Boss、跳过阶段或无条件取消关键机制。

### 14.2 防止无脑选择

- 回生瓶在满生命时没有立即价值。
- 镜盾需要预判危险窗口。
- 定影钉在 Boss 无敌或转阶段时不能使用。
- 不同 Boss 前应提供不同工具，避免形成固定最优解。

### 14.3 重点观察数据

- 每张卡的出现次数、选择次数和选择率。
- 玩家选择工具后的成功率变化。
- 工具实际使用率与剩余未使用率。
- 工具使用时的玩家生命和 Boss 阶段。
- 玩家死亡后再次选择同一工具的比例。
- 跳过率和精华不足率。

## 15. 音画反馈需求

### 15.1 通用反馈

- 装备工具时有明确的入槽动画与确认音。
- 工具按键无效时提供轻量、短促反馈，不能完全无响应。
- 工具成功时需要同时具备角色反馈、目标反馈和 HUD 反馈。
- 使用次数归零时播放独立的耗尽反馈。

### 15.2 美术需求

- 准备卡“工具”类型标签与边框样式。
- 三张首发工具图标。
- 工具 HUD 槽位、次数和禁用遮罩。
- 回生瓶恢复特效。
- 镜盾待机与破碎特效。
- 定影钉生成、减速和结束特效。

### 15.3 音频需求

- 工具装备确认音。
- 工具不可用提示音。
- 回生瓶使用与恢复音。
- 镜盾展开与成功格挡破碎音。
- 定影钉落地、命中和效果结束音。

## 16. 异常与边界处理

| 场景 | 预期处理 |
|---|---|
| 玩家没有足够精华 | 工具卡置灰，不可选择 |
| 玩家选择后快速重复点击 | 只接受第一次有效选择 |
| 选择工具后场景加载失败 | 保留流程错误日志，防止重复扣费 |
| 进入 Mirror 时玩家对象被替换 | 工具状态随持久玩家或会话重新绑定 |
| 工具使用时目标消失 | 判定失败，不扣次数 |
| Boss 正在转阶段 | 禁止控制类工具，给出禁用反馈 |
| 工具效果期间玩家死亡 | 立即终止效果并清空工具状态 |
| 工具效果期间 Boss 死亡 | 终止效果，进入胜利流程并清空状态 |
| 暂停菜单打开 | 不响应工具输入 |
| 返回主菜单或开始新游戏 | 清空全部工具运行时状态 |

## 17. 验收标准

### 17.1 镜前界面

- 每次进入 Mirror 前正确出现三张准备卡。
- 默认组合为两张属性卡和一张工具卡。
- 每张卡正确显示类型、名称、效果、消耗和不可用原因。
- 玩家只能选择一张，也可以跳过。
- 选择后只扣除一次生命精华。

### 17.2 属性卡

- 属性卡效果与现有表现一致。
- 选择属性卡后不会装备工具。
- 属性成长能够随持久玩家进入下一场景。

### 17.3 工具卡

- 选择工具卡后工具槽显示正确工具和次数。
- 选择工具卡后不会应用任何额外属性成长。
- 工具只在 Mirror 内响应使用输入。
- 工具成功生效后才扣除次数。
- 不满足使用条件时不扣次数。
- 工具耗尽后不能继续使用。

### 17.4 生命周期

- Boss 胜利后工具及剩余次数清空。
- 玩家死亡离开 Mirror 后工具及剩余次数清空。
- 返回现实场景后不显示工具 HUD。
- 返回主菜单或开始新游戏后不存在残留工具状态。

### 17.5 稳定性

- 快速连点不会重复消费或重复装备。
- 暂停、剧情、死亡和切场景期间不会误触工具。
- 工具效果不会跨场景残留。
- 工具配置缺失时不会阻断进入 Mirror 的流程。

## 18. 测试场景建议

### 18.1 基础闭环

1. 获得足够生命精华。
2. 击碎镜门。
3. 选择回生瓶。
4. 进入 Mirror，确认 HUD 显示一次。
5. 受伤后使用，确认恢复并耗尽。
6. 击败 Boss，确认工具清空。

### 18.2 余额与重复消费

1. 将余额设置为低于工具价格。
2. 确认工具卡置灰。
3. 将余额设置为刚好等于价格。
4. 快速连续点击工具卡。
5. 确认只扣费一次、只装备一次。

### 18.3 使用条件

1. 满生命时尝试使用回生瓶。
2. 确认不生效、不扣次数。
3. 受伤后再次使用。
4. 确认正常生效并扣次数。

### 18.4 死亡重试

1. 选择工具并进入 Mirror。
2. 在未使用和已使用两种情况下分别死亡。
3. 确认返回现实后工具均清空。
4. 再次进入镜前准备，确认需要重新选择和支付。

### 18.5 场景与状态

1. 在剧情、暂停、受击硬直、死亡和场景切换期间按工具键。
2. 确认工具不被误触。
3. 完成 Boss 转阶段测试，确认控制类工具遵守禁用规则。

## 19. 分阶段范围

### 19.1 最小可玩版本

- 镜前界面支持属性卡与工具卡。
- 固定两属性 + 一工具。
- 单工具槽。
- 独立工具输入。
- 工具 HUD。
- 回生瓶一张工具卡。
- Mirror 胜利、死亡和新游戏时清空。

### 19.2 V1 完整版本

- 增加镜盾。
- 增加定影钉。
- 每个镜门可指定工具卡。
- 完整音画反馈。
- 完成所有异常与生命周期测试。

### 19.3 后续候选

- 同一镜门重试免费恢复工具。
- 按 Boss 标签生成工具候选。
- 工具解锁和收藏图鉴。
- 工具升级、稀有度和多次使用。
- 多工具槽或局内切换。
- 现实关卡中的工具用途。

## 20. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 工具成为固定最优选 | 玩家永远不选属性卡 | 限制次数、提高价格、按 Boss 调整工具，避免直接跳过机制 |
| 工具存在感不足 | 玩家选了但经常忘记使用 | 强化入场 HUD、按键提示和首次教学 |
| 输入负担增加 | 玩家记不住新按键 | V1 只保留一个工具槽和一个统一按键 |
| 死亡后重复付费挫败 | 失败玩家精华快速耗尽 | 观察测试数据，必要时启用同镜门重试免费恢复 |
| 控制类工具破坏 Boss 流程 | 转阶段、无敌、演出被打断 | 用统一兼容标签和 Boss 状态校验禁止使用 |
| 代码继续耦合在属性系统 | 新工具越做越难维护 | 从定义、运行时状态和效果执行三层拆分 |
| 内容成本膨胀 | 每个工具需要独立图标、特效和音效 | 首版只做三种，并优先复用现有反馈资源 |

## 21. 评审时需要确认的问题

以下问题不阻塞本 PRD 作为 V1 方向，但在正式排期前需要由策划确认：

1. 工具是否严格只允许在 Mirror 内使用，还是未来也要服务现实关卡解谜。
2. 死亡重试时是否接受重新付费，还是同一镜门首次购买后免费恢复。
3. 三张卡是否长期固定为“两属性 + 一工具”，还是后续进入统一随机池。
4. 工具默认按键是否采用 R，以及手柄映射方案。
5. 控制类工具能否影响 Boss，还是首版只做玩家自身效果。
6. 生命精华的整体产出是否足以支撑玩家在属性卡与工具卡之间做真实选择。

## 22. 最终建议

建议立项，但将其定义为 **“镜前准备系统的扩展”**，而不是“完整工具卡牌系统”。

首个验证版本只需要让一张回生瓶工具卡走通以下闭环：

**镜前出现 → 消费选择 → 装备工具 → Mirror HUD 显示 → 主动使用 → 次数耗尽 → 离开 Mirror 清空。**

当这条闭环在操作、反馈和取舍上被验证有效后，再增加镜盾和定影钉。这样既能利用现有三选一流程，也能避免在玩法尚未验证前过早建设背包、卡池和大量工具内容。

# 生命资源系统升级技术方案

> 文档状态：设计提案  
> 更新时间：2026-08-07  
> 适用范围：关卡玩法、玩家战斗、生命恢复、花草资源、永久成长与存档  
> 当前阶段：只确定系统结构和第一阶段落地范围，暂不实现菜单与手动合成

## 1. 改造目标

本次改造将现有“攻击花草获得生命储备”的单一补给系统，升级为由战斗循环与长期成长共同驱动的生命系统。

核心目标如下：

1. 玩家通过对敌人造成有效伤害获得生命能量，使进攻、续航和风险管理形成直接循环。
2. 花草不再直接补充当前生命能量，而是产出生命精华，用于增加角色的永久属性。
3. 当前阶段不制作背包菜单、合成菜单或配方选择。生命精华自动累计，达到条件后自动增加属性。
4. 永久成长数据跨关卡、死亡和重新进入游戏保留。
5. 所有内容统一属于关卡生命玩法，不区分“关卡内探索”和“局外玩法”。“永久”只表示数据的保存周期，不代表另有一套局外操作流程。
6. 底层采用可扩展结构，未来可以加入多种素材、合成、祭坛、技能消耗和构筑选择，而不需要推翻第一阶段实现。

## 2. 核心玩法循环

```text
玩家进入关卡
    ↓
攻击敌人并造成有效伤害
    ↓
按比例获得当前生命能量
    ↓
受伤后消耗生命能量进行恢复或释放生命类能力
    ↓
攻击关卡中的花草节点
    ↓
获得生命精华并自动累计
    ↓
达到成长阈值后自动增加永久属性
    ↓
属性写入存档，并影响当前及后续关卡
```

系统中存在两类用途完全不同的资源：

| 资源 | 主要来源 | 主要用途 | 生命周期 |
| --- | --- | --- | --- |
| 当前生命能量 | 对敌人造成有效伤害 | G 恢复及未来生命技能 | 临时战斗资源，按关卡规则重置 |
| 生命精华 | 摧毁花草资源节点 | 自动兑换永久属性 | 永久保存 |

二者必须在数据、接口和 UI 上分离，避免“花草既是即时回血包，又是永久成长资源”的职责混乱。

## 3. 第一阶段确定规则

### 3.1 生命能量获取

玩家对合法敌人造成实际伤害时，按照实际伤害值的一定比例获得生命能量。

基础公式：

```text
本次原始能量 = 实际伤害 × 基础转化比例 × 玩家转化倍率
最终获得能量 = 经过小数累计与取整后的原始能量
当前生命能量 = Clamp(当前生命能量 + 最终获得能量, 0, 能量槽上限)
```

“实际伤害”指敌人本次真正损失的生命值，而不是攻击面板伤害。例如敌人只剩 3 点生命，玩家造成 10 点攻击伤害，本次最多按 3 点伤害转化能量。

首版建议规则：

- 只计算玩家直接造成并成功结算到敌人生命值上的伤害。
- 不计算攻击花草、机关、无敌目标、护盾完全吸收、过量伤害和无效伤害。
- 同一次伤害只能结算一次生命能量。
- 持续伤害是否产能由伤害标签配置，默认允许，但每次按实际结算值计算。
- 环境击杀、敌人互伤和反弹伤害默认不产能。
- 能量槽已满时，多余能量直接舍弃；未来可以通过升级增加溢出转化能力。
- 小数部分保存在内部累计器中，避免低伤害或低转化率攻击永远无法获得能量。

示例：玩家实际造成 17 点伤害，基础转化比例为 20%，玩家转化倍率为 1.1，则产生 `17 × 0.2 × 1.1 = 3.74` 点原始能量。系统发放 3 点，并保留 0.74 到后续结算。

### 3.2 生命能量槽

生命能量槽必须与玩家最大生命值解耦。

```text
最终能量槽上限 = 基础槽上限 + 永久槽上限加成 + 临时加成
```

现有 `PlayerHealthReserve.Capacity` 直接读取 `Health.maxHP`，升级时需要替换为独立的容量计算。最大生命和能量槽上限是两个不同属性，可以分别成长。

建议第一阶段保留整数能量，便于沿用现有 G 恢复逻辑。若后续所有公式需要更细粒度，再把内部存储统一升级为浮点数或定点数。

### 3.3 生命能量消费

第一阶段继续保留 G 恢复技能：

- 玩家缺少生命值且拥有生命能量时，可以施放恢复。
- 恢复量不超过当前缺失生命值。
- 实际消耗量由恢复效率决定。
- 施放、生效点、移动锁定和打断规则可暂时沿用现有 `PlayerRecoveryAbility`。

建议把现有“预扣后被打断不返还”改成可配置规则：

```text
ConsumeOnCastStart：开始施放时消耗，打断不返还
ConsumeOnCommit：恢复生效时消耗，生效前打断不消耗
```

第一阶段可继续使用 `ConsumeOnCastStart`，以保持现有手感，后续通过配置调整。

未来生命能量还可以被其他能力消费，例如临时护盾、濒死保护、强化攻击或主动技能。所有消费者应通过统一消费接口扣除能量，不直接修改字段。

### 3.4 花草与生命精华

花草仍然是关卡内可放置、可攻击并有耐久的玩法节点，但不再直接增加当前生命能量。

花草耗尽后的新流程：

```text
花草耐久归零
    ↓
确定生命精华奖励数量
    ↓
立即写入永久成长账户
    ↓
检查是否达到下一级成长阈值
    ↓
自动提升属性并写入存档
    ↓
播放精华飞向玩家及属性提升反馈
```

第一阶段只使用一种通用资源“生命精华”，不向玩家展示复杂背包。底层可以把它视为只有一种素材的轻量账户，而不是完整 RPG 背包。

建议花草首版只负责以下配置：

- 节点耐久。
- 按伤害或按攻击次数扣除耐久。
- 生命精华奖励数量。
- 受击、耗尽和奖励表现。
- 是否参与一次性采集状态保存；首版可继续沿用重载关卡恢复节点的规则。

### 3.5 自动成长

生命精华达到当前阈值后，系统自动消耗对应数量，并将指定永久属性增加一点。当前阶段不弹出菜单，也不要求玩家进行合成操作。

推荐首版只开放一个自动成长方向：

```text
生命能量槽永久等级 +1
```

每级提供的容量增加量和升级所需精华均由配置表控制：

```text
升级后槽上限 = 基础槽上限 + 永久等级 × 每级容量加成
下一等级精华需求 = 成长曲线[当前永久等级]
```

当一次奖励跨过多个阈值时，允许连续升级，直到剩余精华不足。升级过程必须先完成数据结算和存档，再播放表现，避免切换场景时丢失成长。

未来扩展时，可以将单一路线替换为多个成长属性：

| 属性标识 | 作用 |
| --- | --- |
| `EnergyCapacity` | 增加生命能量槽上限 |
| `DamageConversionRate` | 增加伤害转生命能量的比例 |
| `RecoveryEfficiency` | 降低恢复相同生命值所需的能量 |
| `MaxHealth` | 增加最大生命值 |
| `OverflowRetention` | 将部分溢出能量转为其他收益 |

在没有菜单和选择机制前，不建议同时自动升级多个属性，否则玩家难以理解成长来源，也不利于平衡。

## 4. 数据生命周期

### 4.1 临时战斗数据

以下数据属于当前关卡生命玩法状态：

- 当前生命能量。
- 能量转化的小数余量。
- 当前恢复施法状态。
- 花草节点本次加载中的耐久和耗尽状态。

第一阶段建议当前生命能量在玩家死亡和开始新关卡时清空。场景之间是否携带可由关卡规则配置，不影响永久成长数据。

### 4.2 永久成长数据

以下数据写入玩家存档：

- 当前未消费的生命精华。
- 各永久属性等级。
- 存档数据版本。

最小存档结构示例：

```csharp
[Serializable]
public sealed class PlayerLifeProgressData
{
    public int version = 1;
    public int lifeEssence;
    public int energyCapacityLevel;
}
```

永久数据应在以下时机保存：

- 获得生命精华后。
- 自动升级完成后。
- 正常退出或切换关卡前。

为避免奖励重复或丢失，推荐采用“结算后立即保存”的方式。奖励表现不参与存档事务。

## 5. 建议系统架构

### 5.1 模块职责

| 模块 | 建议职责 |
| --- | --- |
| `PlayerLifeEnergy` | 保存当前生命能量、独立容量、增减与事件通知 |
| `LifeEnergyGainProcessor` | 接收玩家造成的实际伤害，执行转化公式和小数累计 |
| `PlayerRecoveryAbility` | 输入、施放、打断和恢复结算，通过统一接口消费能量 |
| `LifeResourceNode` | 花草耐久、玩家攻击过滤、受击反馈和精华奖励请求 |
| `PlayerLifeProgression` | 保存生命精华、检查阈值、执行自动永久升级 |
| `PlayerAttributeProvider` | 汇总基础值、永久成长和临时加成，向其他系统提供最终属性 |
| `LifeProgressionConfig` | 转化比例、基础容量、每级加成、成长曲线等静态配置 |
| `LifeProgressSaveService` | 加载、保存、版本迁移和异常数据修复 |
| `LifeSystemPresenter` | HUD、飘字、飞行特效和升级提示，只订阅事件不决定规则 |

### 5.2 依赖方向

```text
敌人伤害结算
    → LifeEnergyGainProcessor
        → PlayerLifeEnergy
            → HUD / 表现

花草节点
    → PlayerLifeProgression
        → PlayerAttributeProvider
        → LifeProgressSaveService
        → HUD / 升级表现

PlayerRecoveryAbility
    → PlayerLifeEnergy
    → Health
```

伤害系统只负责报告“玩家对哪个目标造成了多少实际伤害”，不应直接理解生命能量公式。花草节点只提交精华奖励，不应直接修改属性等级或操作存档。

### 5.3 关键接口建议

```csharp
public interface ILifeEnergyWallet
{
    int Current { get; }
    int Capacity { get; }
    int Add(int amount, LifeEnergySource source);
    bool TryConsume(int amount, LifeEnergySpendReason reason);
}

public interface IPlayerDamageDealtListener
{
    void OnPlayerDamageDealt(in DamageDealtResult result);
}

public interface ILifeProgression
{
    int LifeEssence { get; }
    int AddEssence(int amount, string sourceId);
}
```

`DamageDealtResult` 至少应包含：攻击者、目标、请求伤害、实际伤害、伤害类型、是否为持续伤害、是否允许生命能量转化和唯一结算标识。

## 6. 配置设计

建议使用一个 `ScriptableObject` 保存全局默认配置，并允许关卡或玩家角色覆盖必要参数。

```csharp
[CreateAssetMenu(menuName = "Mirror Trial/Life/Life Progression Config")]
public sealed class LifeProgressionConfig : ScriptableObject
{
    public int baseEnergyCapacity;
    public float baseDamageConversionRate;
    public int capacityPerPermanentLevel;
    public int[] essenceRequiredByLevel;
    public bool allowDamageOverkill;
    public bool allowDamageOverTime;
}
```

配置要求：

- 数值不散落在玩家、敌人、花草和 UI 脚本中。
- 所有比例明确使用 0 到 1，或明确使用百分数，不混用。
- 成长曲线到达数组末尾时必须有清晰行为：达到等级上限，或使用公式继续增长。
- 编辑器中对负数、空数组和不递增阈值进行校验。

## 7. UI 与反馈

第一阶段无需菜单，但需要最小信息反馈：

- HUD 显示当前生命能量与槽上限。
- 造成伤害并获得能量时，能量槽有短促增长反馈。
- 能量已满时，不持续播放误导性的获取反馈。
- 花草耗尽时显示获得的生命精华数量。
- 自动升级时显示“生命能量槽上限 +X”。
- 可选显示简洁进度，如“生命精华 6/10”，但不允许从该界面进行操作。

所有 UI 都通过事件读取状态：

```csharp
LifeEnergyChanged(current, capacity)
LifeEssenceChanged(current, requiredForNextLevel)
PermanentAttributeUpgraded(attributeId, oldLevel, newLevel, valueDelta)
```

## 8. 与现有系统的迁移关系

### 8.1 保留内容

- `HealthResourceNode` 的耐久、攻击来源过滤和受击反馈可以复用。
- `HealthResourceTransferEffect` 可以改为表现生命精华飞向玩家。
- `HealthResourceCatalog` 与关卡编辑器的资源节点放置流程可以继续使用。
- `PlayerRecoveryAbility` 的输入、施法和打断框架可以保留。
- `PlayerHealthReserve` 的事件通知和增减模式可以作为新能量钱包的改造基础。

### 8.2 必须改变的耦合

1. `PlayerHealthReserve.Capacity` 不再读取 `Health.maxHP`，改为读取独立生命属性计算结果。
2. `HealthResourceNode.DestroyNode` 不再调用 `PlayerHealthReserve.Add(healthReward)`，改为向永久成长系统提交生命精华。
3. 敌人生命结算需要暴露实际伤害结果，供 `LifeEnergyGainProcessor` 监听。
4. 原有“固定生命奖励”字段迁移为“生命精华奖励”。
5. 场景切换只重置临时战斗数据，不得清除永久成长数据。

### 8.3 命名迁移建议

为了降低一次性重构风险，可以先保留脚本文件名，通过内部语义完成迁移，稳定后再统一重命名：

| 现有名称 | 目标名称 |
| --- | --- |
| `PlayerHealthReserve` | `PlayerLifeEnergy` |
| `HealthResourceNode` | `LifeResourceNode` 或 `LifeEssenceNode` |
| `healthReward` | `lifeEssenceReward` |
| `HealthResourceTransferEffect` | `LifeEssenceTransferEffect` |

Unity 脚本和序列化字段重命名时应使用 `MovedFrom`、`FormerlySerializedAs` 或分阶段迁移，避免 Prefab 引用和已配置数值丢失。

## 9. 防重复与异常处理

- 每次伤害结算应拥有唯一标识，能量处理器需要防止同一伤害事件重复消费。
- 花草耗尽必须有幂等保护，一个节点只能发放一次精华。
- 精华和永久等级读取后必须进行非负校验。
- 存档版本不兼容时执行迁移，不直接覆盖玩家成长。
- 升级时先扣除精华、增加等级并保存，再发出表现事件。
- 容量降低时，当前生命能量应压到新上限，并通知 HUD。
- 找不到永久成长组件时，花草节点应记录明确错误；不应静默把奖励改发为当前能量。

## 10. 分阶段实施计划

### 阶段一：建立可玩的核心闭环

1. 将生命能量容量与最大生命值解耦。
2. 为敌人伤害系统增加“实际伤害已结算”事件。
3. 实现伤害按比例转化生命能量及小数累计。
4. 将花草奖励改为生命精华。
5. 实现生命精华自动升级能量槽上限。
6. 实现最小永久存档。
7. 更新 HUD 和获得反馈。

阶段一明确不包含：背包界面、合成界面、配方、材料分类、成长选择树和局外操作场景。

### 阶段二：完善数据与关卡配置

1. 增加伤害标签和不同攻击的产能规则。
2. 增加多档成长曲线和等级上限。
3. 支持不同花草的精华产量与稀有度。
4. 完善编辑器校验、调试面板和数值统计。
5. 增加旧存档迁移和自动化测试。

### 阶段三：按玩法需求扩展大系统

可选扩展包括：

- 多种生命素材。
- 祭坛或培育台交互。
- 手动合成与配方。
- 多属性成长选择。
- 生命技能与不同能量消费策略。
- 溢出能量、连击倍率、处决奖励和风险增益。

阶段三是在既有“资源账户—转化规则—属性系统”上增加交互方式，不改变核心数据流。

## 11. 测试与验收标准

### 11.1 战斗产能

- 玩家造成 0 点实际伤害时不获得能量。
- 攻击无敌目标、花草和非敌对目标时不获得能量。
- 过量伤害默认不参与转化。
- 多段攻击每段只结算一次。
- 小数能量能够跨攻击累计。
- 当前能量永远不超过独立槽上限。
- 永久容量升级后，当前 HUD 立即显示新上限。

### 11.2 花草与成长

- 花草耐久归零只发放一次生命精华。
- 花草不再增加当前生命能量。
- 精华不足时只累计，不升级。
- 达到阈值时自动扣除精华并升级。
- 一次获得大量精华时可以连续升级。
- 升级后重新加载关卡、死亡和重新启动游戏，永久等级仍然保留。
- 当前阶段全流程不需要打开任何菜单。

### 11.3 恢复与生命周期

- G 恢复只消费当前生命能量，不消费生命精华。
- 满血时不能发起无意义恢复。
- 消耗、打断和生效时机符合配置。
- 新关卡或死亡只重置临时生命能量，不清除生命精华和永久等级。
- 存档损坏或字段缺失时使用安全默认值并记录错误。

## 12. 数值观察指标

系统上线调试后至少记录以下数据，以便调整平衡：

- 每个关卡玩家造成的总实际伤害。
- 理论产能、实际写入能量和溢出浪费量。
- G 恢复次数、恢复量和打断次数。
- 玩家死亡时的当前能量。
- 每关获得的生命精华数量。
- 达成每个永久等级所需的平均关卡数。

初始数值不应只凭感觉固定。建议先让普通战斗中玩家通过积极进攻获得可感知但不能无限维持的恢复能力，再通过统计调整转化比例、槽上限和成长曲线。

## 13. 当前结论

本系统的第一阶段最终形态为：玩家在关卡中攻击敌人，通过实际伤害按比例获得当前生命能量；生命能量用于 G 恢复及未来生命技能；玩家攻击花草获得生命精华，生命精华自动累计并自动提升生命能量槽上限；升级结果永久保存。整个流程不需要背包菜单、合成菜单或额外的局外场景，但底层已经拆分为可扩展的资源、转化、属性和存档模块，后续可以逐步发展为包含多素材、合成和构筑选择的大型生命生态系统。

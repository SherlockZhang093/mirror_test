# 生命资源系统升级 PRD

> 文档状态：需求定稿  
> 更新时间：2026-08-07  
> 适用项目：《破映·在破碎中，找回自己》Demo  
> 当前范围：战斗生命能量、花草生命精华、单次游戏会话全局账户  
> 明确不包含：卡牌系统、关末三选一界面、磁盘存档、主菜单与继续游戏

## 1. 产品背景

当前生命资源系统主要通过攻击花草获得生命储备，再使用 G 键恢复生命。该结构让花草同时承担即时恢复与长期成长入口，资源职责不够清晰，也无法形成“积极战斗获得续航、探索花草积累成长资源”的双循环。

本次升级将生命玩法拆分为两种互不混用的资源：

1. **当前生命能量**：玩家通过对敌人造成实际伤害获得，用于当前战斗中的 G 恢复及未来生命类能力。
2. **生命精华**：玩家通过首次摧毁花草资源节点获得，作为后续关末成长系统使用的全局会话货币。

Demo 不制作永久存档。生命精华和节点领取状态仅在本次游戏运行期间全局保留，完全退出并重新启动游戏后全部重新开始。

## 2. 产品目标

### 2.1 核心目标

- 建立“进攻产生生命能量、生命能量支持恢复”的战斗续航循环。
- 让花草从即时回血来源转变为探索成长资源来源。
- 让生命精华在当前游戏会话中跨场景、跨死亡全局持有。
- 防止玩家通过反复重载关卡重复领取同一花草的精华。
- 将资源结算与视觉表现分离，确保特效中断不会影响实际奖励。
- 为后续关末固定三选一卡牌系统提供稳定、简单的精华查询与消费接口。

### 2.2 成功标准

玩家能够明确理解：

```text
打敌人 → 获得当前生命能量 → 按 G 恢复生命
打花草 → 获得生命精华 → 供后续关末成长消费
```

两类资源在来源、用途、生命周期和 UI 表现上均不混淆。

## 3. 非目标

本阶段不实现以下内容：

- 不实现卡牌生成、固定三选一、卡牌 UI 或卡牌效果。
- 不实现背包、材料分类、合成、配方或商店。
- 不实现 JSON、PlayerPrefs 或其他磁盘存档。
- 不实现存档版本、读档、旧数据迁移或多存档档位。
- 不实现返回主菜单、继续游戏或运行中主动开始新周目。
- 不实现多种生命素材。
- 不让花草 Prefab 直接增加最大生命、能量容量或其他玩家属性。

## 4. 核心概念

| 概念 | 定义 |
| --- | --- |
| 当前生命能量 | 当前战斗使用的临时资源，由玩家对敌人造成实际伤害获得 |
| 生命精华 | 当前游戏会话全局持有的成长货币，由花草节点首次被摧毁时获得 |
| 游戏会话 | 从启动游戏程序到完全退出游戏程序的完整运行周期 |
| 首次采集 | 某个花草节点的稳定唯一 ID 在本次游戏会话中尚未领取过奖励 |
| 已采集节点 | 本次游戏会话中已经发放过精华的花草节点 |
| 稳定节点 ID | 用于跨场景重载识别同一个花草节点的唯一字符串标识 |

## 5. 整体玩法循环

```text
启动游戏
→ 创建全局会话数据
→ 玩家进入关卡

战斗分支：
攻击敌人并造成实际伤害
→ 按实际伤害转化生命能量
→ 消耗生命能量使用 G 恢复

探索分支：
攻击花草并使其耐久归零
→ 检查稳定节点 ID
→ 本次会话未领取：立即增加生命精华并记录已领取
→ 本次会话已领取：不增加生命精华
→ 两种情况都正常播放花草破碎表现

切换场景、死亡或重载关卡
→ 全局生命精华和已领取节点记录继续保留

完全退出游戏并重新启动
→ 所有会话数据重新开始
```

## 6. 资源规则

### 6.1 当前生命能量

#### 来源

玩家对合法敌人造成实际伤害时，按照实际伤害值转化当前生命能量。

```text
原始能量 = 实际伤害 × 基础转化比例 × 玩家转化倍率
最终获得能量 = 原始能量经过小数累计与取整后的结果
当前能量 = Clamp(当前能量 + 最终获得能量, 0, 能量槽上限)
```

“实际伤害”指目标本次真正损失的生命值，不包括过量伤害。例如敌人只剩 3 点生命，玩家攻击面板伤害为 10，本次最多按 3 点伤害转化。

#### 合法产能条件

- 必须由玩家直接造成。
- 必须成功结算到合法敌人的生命值。
- 同一次伤害结算只能产能一次。
- 攻击花草、机关、无敌目标和非敌对目标不产能。
- 护盾完全吸收、0 点实际伤害和无效伤害不产能。
- 环境击杀、敌人互伤和反弹伤害默认不产能。
- 持续伤害是否产能由伤害标签决定；首版默认允许，并按每次实际伤害结算。
- 能量槽已满时，多余能量舍弃，不播放误导性的持续获得反馈。
- 小数余量在内部累计，避免低伤害攻击长期无法产能。

#### 容量

生命能量槽上限必须与玩家最大生命值解耦：

```text
最终能量槽上限 = 基础容量 + 会话成长加成 + 临时加成
```

首版继续使用整数能量。现有 `PlayerHealthReserve.Capacity` 不再直接读取 `Health.maxHP`。

#### 消费

首版继续支持 G 恢复：

- 玩家存在缺失生命且拥有足够生命能量时才能施放。
- 恢复量不得超过缺失生命值。
- 消耗和打断框架沿用现有 `PlayerRecoveryAbility`。
- 首版保持开始施放时扣除、打断不返还的现有规则。
- 所有能力必须通过统一消费接口扣除生命能量，不得直接修改资源字段。

### 6.2 生命精华

#### 来源

- 仅由花草资源节点在本次游戏会话内首次被摧毁时发放。
- 每个花草 Prefab 实例配置固定的精华奖励数量。
- 精华奖励数量必须大于等于 0。
- 花草不再增加当前生命能量。

#### 用途

- 本 PRD 只提供精华账户及消费接口。
- 后续关末固定三选一卡牌系统可查询余额并请求消费。
- 精华系统不理解卡牌内容，也不直接修改玩家属性。

#### 生命周期

| 场景 | 精华余额 | 已领取节点记录 |
| --- | --- | --- |
| 普通场景切换 | 保留 | 保留 |
| 现实层进入镜中层 | 保留 | 保留 |
| 玩家死亡并重载 | 保留 | 保留 |
| 重新进入已经到过的关卡 | 保留 | 保留 |
| 完全退出游戏 | 清空 | 清空 |
| 重新启动游戏 | 从零开始 | 从零开始 |

精华数据只存在于内存，不写入任何磁盘文件。

## 7. 花草节点规则

### 7.1 Prefab 配置

每个花草资源节点至少包含：

| 字段 | 作用 |
| --- | --- |
| `resourceNodeId` | 本次游戏会话内识别节点的稳定唯一 ID |
| `durability` | 节点耐久 |
| `countHitsInsteadOfDamage` | 是否按攻击次数而不是伤害值扣除耐久 |
| `lifeEssenceReward` | 首次摧毁时发放的生命精华数量 |
| 受击表现配置 | 受击闪烁、音效、粒子等 |
| 破碎表现配置 | 破碎动画、音效、粒子等 |
| 精华获得表现配置 | 飞向玩家、飘字和 HUD 跳动等 |

花草 Prefab 不配置具体属性强化效果。

### 7.2 稳定节点 ID

推荐格式：

```text
{LevelId}.{ResourceType}.{Sequence}
```

示例：

```text
Level_Reality_01.LifePlant.001
Level_Reality_01.LifePlant.002
Level_Reality_02.LifeShrine.001
```

要求：

- ID 不能为空。
- 同一游戏内容中不能存在重复 ID。
- 复制节点时必须生成新的 ID。
- 场景重载和 LevelConfig 重新生成后，同一逻辑节点的 ID 必须保持不变。
- 编辑器应提供空 ID、重复 ID 和非法奖励数量校验。

### 7.3 首次摧毁流程

```text
耐久归零
→ 执行节点本地幂等检查
→ 向全局会话账户提交 resourceNodeId 与 reward
→ 账户确认本次会话未领取
→ 先记录 resourceNodeId
→ 立即增加生命精华
→ 发出余额变化与领取成功事件
→ 花草播放破碎表现
→ 播放精华飞行、获得飘字和 HUD 反馈
```

规则结算必须先于表现。精华飞行特效仅用于反馈，不决定奖励何时到账。

### 7.4 重复摧毁流程

当玩家重载关卡并再次摧毁同一花草时：

```text
耐久归零
→ 全局会话账户发现 resourceNodeId 已领取
→ 返回领取失败/已领取结果
→ 不增加精华
→ 正常播放花草破碎表现
→ 不播放精华飞行、获得飘字和精华 HUD 增长反馈
```

花草依然可以被攻击和打碎，不需要在重载后永久隐藏或禁用。

## 8. 会话全局数据

### 8.1 数据内容

```text
当前生命精华余额
本次会话已经领取过的资源节点 ID 集合
```

建议概念结构：

```csharp
public sealed class GameSessionProgress
{
    public int LifeEssence { get; }
    public IReadOnlyCollection<string> ClaimedResourceNodeIds { get; }

    public bool TryClaimLifeEssence(string nodeId, int amount);
    public bool CanSpendLifeEssence(int amount);
    public bool TrySpendLifeEssence(int amount, string reasonId);
}
```

### 8.2 存在方式

- 使用单一 `DontDestroyOnLoad` 会话对象跨场景持有。
- 场景中重复创建时只保留一个实例。
- 不挂在 Player Prefab 上，避免玩家重建时丢失。
- 不由单个关卡的 `LevelManager` 持有，避免场景卸载时丢失。
- 游戏启动时初始化一次。
- 游戏完全退出后由进程自然销毁。
- 不实现写盘与读盘。

### 8.3 Unity 编辑器行为

若项目关闭了 Domain Reload，静态字段可能在多次 Play 之间残留。必须在新的 Play 会话开始时显式清空会话数据，确保编辑器中的“停止后再次运行”等同于重新启动游戏。

## 9. 事件与表现

### 9.1 规则事件

建议提供：

```csharp
LifeEssenceChanged(oldValue, newValue)
LifeEssenceClaimed(nodeId, amount)
LifeEssenceSpendSucceeded(amount, reasonId)
LifeEssenceSpendFailed(amount, reasonId)
```

当前生命能量继续提供：

```csharp
LifeEnergyChanged(current, capacity)
LifeEnergyGained(amount, source)
LifeEnergySpent(amount, reason)
```

### 9.2 表现原则

- 表现层只订阅规则事件，不直接修改余额。
- 精华首次领取成功后才播放精华飞行和获得飘字。
- 重复节点不播放奖励反馈。
- 飞行特效被跳过、中断或销毁，不影响已经到账的精华。
- HUD 显示的数值以账户状态为准，不以动画中间值为准。

### 9.3 最小 UI

本阶段只要求：

- HUD 能显示当前生命能量与上限。
- HUD 或简洁区域能显示当前全局生命精华余额。
- 获得生命能量时播放短促增长反馈。
- 首次获得精华时显示“生命精华 +X”。
- 重复摧毁已领取花草时不显示奖励增长反馈。

生命精华的完整 UI 设计见第 10 节。

## 10. 生命精华 UI 设计

### 10.1 设计定位

生命精华是全局会话货币，不与任何单一关卡场景绑定，因此它的 UI 归属玩家主 HUD，而不是某个关卡界面。

设计原则：

1. **识别优先**：玩家必须能一眼区分“生命能量（临时战斗资源）”与“生命精华（全局成长货币）”，两者颜色、形状和位置均不同。
2. **低常驻权重**：精华余额不是高频操作对象，常驻时保持克制，只在获得和消费时短暂提高存在感。
3. **数据权威在账户**：UI 只订阅 `GameSessionProgress` 的状态与事件，永远不做本地扣减或补偿显示。
4. **结算先行**：余额数字在规则结算的同一帧更新，飞行特效只负责“讲故事”，不允许数字等待动画。

### 10.2 屏幕布局

生命精华计数器是独立于生命 HUD 的界面元素，固定放在**屏幕右上角**：

```text
┌──────────────────────────────────────┐
│                        ◆ 12（精华）  │ ← 右上角独立计数器
│                                      │
│   （游戏画面）                        │
│                                      │
│ ♥♥♥♥♡                                │
│ ▔▔▔▔▔▔▔▔▔▔  ← 左上角仍为生命 HUD     │
└──────────────────────────────────────┘
```

- 计数器锚定在屏幕右上角，距右边缘与上边缘各留安全边距（建议 24px，随分辨率锚点缩放）。
- 与左上角生命 HUD 形成对角分布：临时战斗资源在左，全局成长货币在右，玩家不会混淆。
- 计数器整体保持低视觉权重，不占用屏幕中央区域。
- Boss 战、受伤闪红、低血警告等 ScreenFx 均不遮挡精华计数器（Canvas 排序值 100，高于遮罩 50）。

### 10.3 计数器结构

```text
LifeEssenceCounter
├── Icon        （精华图标：小型镜露/碎晶形状）
├── ValueText   （整数余额，如 “12”）
└── GainAnchor  （“+X” 飘字的挂点）
```

约束：

- 图标使用**冷青白色镜能**（延续第一关生命资源的青白闪光与镜露圣龛配色），与生命值的红/白色系、能量条颜色明确区分。
- 不使用条形容器：精华没有上限概念，只做“图标 + 整数”的纯计数显示。
- 图标与文字同高对齐，整体高度不超过生命格高度的 80%。
- 余额为 0 时仍然显示 `◆ 0`，不隐藏，保证玩家始终知道该资源存在。

### 10.4 状态与反馈

| 事件 | UI 反馈 |
| --- | --- |
| 首次获得精华 | 数字立即更新；计数器做一次短促缩放脉冲（约 0.2s）；`GainAnchor` 处飘出“+X”并向上淡出 |
| 精华飞行特效到达 | 可选：计数器再做一次更轻的呼吸闪动，作为表现收束；不得在此时才修改数字 |
| 消费成功 | 数字立即更新为新余额；计数器做一次轻微下沉抖动 |
| 消费失败（余额不足） | 计数器整体做一次左右快速抖动并短暂偏红（约 0.3s），随后恢复冷青白色 |
| 重复摧毁已领取花草 | 无任何 UI 反馈 |
| 新会话开始 | 数字直接显示 0，无清零动画 |

反馈参数建议：

```text
获得脉冲：缩放 1.0 → 1.25 → 1.0，总时长 0.2s
获得飘字：字号与计数器文字相同，上浮 24px，0.6s 内淡出
消费失败：水平 ±4px 抖动 3 次，红色叠加 0.3s 渐出
```

### 10.5 数据绑定

新增表现组件（命名建议）：

```csharp
public sealed class LifeEssenceHudView : MonoBehaviour
```

职责：

- `Awake/OnEnable` 订阅 `GameSessionProgress.LifeEssenceChanged` 与 `LifeEssenceClaimed`。
- `OnDisable` 必须退订，避免场景切换后悬空引用。
- 收到 `LifeEssenceChanged` 时直接把 `ValueText` 设为最新余额。
- 收到 `LifeEssenceClaimed` 时播放获得脉冲与“+X”飘字。
- 收到 `LifeEssenceSpendFailed` 时播放余额不足抖动。
- 不缓存、不推算余额，不做任何写操作。

### 10.6 Prefab 与关卡接入

- 生命精华 UI 是一个**独立的 Prefab**（建议 `Assets/MirrorTrial/Resources/UI/LifeEssenceHudUI.prefab`），不作为生命 HUD 的子元素。
- Prefab 自带一个 Screen Space - Overlay 的 Canvas，排序值 100（与主 HUD 同级，高于 ScreenFx 遮罩 50），并带 CanvasScaler 做分辨率适配。
- Prefab 根节点挂 `LifeEssenceHudView`，内部结构为 `LifeEssenceCounter（Icon / ValueText / GainAnchor）`，锚定屏幕右上角。
- 实例化与生命周期跟随 `GameSessionProgress`：会话对象初始化时实例化一次并 `DontDestroyOnLoad`，Reality、Mirror 与关卡切换均不销毁、不重复创建。
- 不接入 `LevelConfig.playerHealthHudPrefab`，不随关卡切换样式；全局统一样式。
- 不挂在 Player Prefab 上，玩家死亡重建不影响精华 UI。

### 10.7 与精华飞行特效的关系

```text
花草破碎
→ 规则层立即入账并发出事件
→ UI 数字同一帧更新
→ 飞行特效独立播放（视觉从花草飞向玩家/计数器方向）
→ 特效结束只触发可选的收束闪动
```

- 飞行特效可以瞄准 `GainAnchor` 的方向播放，但不得持有对 UI 数字的写权限。
- 特效被场景切换打断时，余额和 UI 均保持正确，无需补偿逻辑。

## 11. 对外接口边界

### 11.1 提供给花草节点

```text
TryClaimLifeEssence(nodeId, amount)
```

返回值用于决定是否播放精华获得表现。

### 11.2 提供给后续卡牌系统

```text
LifeEssence
CanSpendLifeEssence(amount)
TrySpendLifeEssence(amount, reasonId)
```

精华系统不负责：

- 生成候选卡牌；
- 判断卡牌稀有度；
- 应用属性效果；
- 控制关末界面；
- 决定每关购买次数。

### 11.3 提供给 UI/表现

通过只读状态和事件提供数据，不允许 UI 直接修改资源字段。

## 12. 异常与边界处理

- `nodeId` 为空时不发放精华，并记录明确错误。
- `amount < 0` 时拒绝发放或消费，并记录明确错误。
- `amount == 0` 时可完成节点破碎，但不播放奖励反馈。
- 同一节点同一帧收到多次耗尽调用时，只允许一次结算成功。
- 同一个 `nodeId` 被不同节点使用时，全局只允许首次发奖，并在编辑器校验中报告重复 ID。
- 全局会话对象缺失时应记录明确错误，不得把精华改发为当前生命能量。
- 全局会话对象重复时只保留一个权威实例。
- 消费超过当前余额时失败，余额不得变为负数。
- 当前生命能量和生命精华均不得出现负数。
- 能量容量降低时，当前生命能量压缩到新上限并通知 HUD。

## 13. 验收标准

### 13.1 战斗生命能量

- 玩家造成 0 点实际伤害时不获得能量。
- 攻击无敌目标、花草、机关和非敌对目标时不获得能量。
- 过量伤害不参与能量转化。
- 多段攻击每段只结算一次。
- 小数能量可以跨攻击累计。
- 当前能量不超过独立能量槽上限。
- 最大生命值变化不会自动改变能量槽上限。
- G 恢复只消费当前生命能量，不消费生命精华。

### 13.2 花草与生命精华

- 花草首次被摧毁时立即增加正确数量的精华。
- 精华到账不依赖飞行特效是否播放完成。
- 首次摧毁后记录稳定节点 ID。
- 同一节点在本次游戏会话中只能发奖一次。
- 重载关卡后同一花草仍然可以被攻击和打碎。
- 重复打碎已领取节点时不增加精华。
- 重复打碎时不播放精华飞行和获得飘字。
- 不同稳定 ID 的花草可以分别发奖。
- 花草不再增加当前生命能量。

### 13.3 会话生命周期

- 普通场景切换后精华余额保留。
- 现实层与镜中层切换后精华余额保留。
- 玩家死亡并重载后精华余额保留。
- 玩家死亡并重载后已领取节点记录保留。
- 完全退出并重新启动游戏后精华余额归零。
- 完全退出并重新启动游戏后所有节点可以重新领取。
- Unity 编辑器停止 Play 后重新 Play，不残留上一轮会话数据。
- 工程运行期间不会生成生命精华存档文件。

### 13.4 接口边界

- UI 只能订阅状态与事件，不能直接修改余额。
- 花草只能提交奖励请求，不能直接操作玩家属性。
- 后续卡牌系统可以查询和消费精华，但精华系统不依赖卡牌类型。
- 消费失败时余额保持不变。

### 13.5 生命精华 UI

- 精华计数器与生命值、生命能量在颜色、形状和位置上可明确区分。
- 精华余额为 0 时计数器仍然可见。
- 获得精华时数字与规则结算同帧更新，不等待飞行特效。
- 飞行特效被场景切换打断后，计数器仍显示正确余额。
- 重复摧毁已领取花草时计数器无任何反馈。
- 消费失败播放余额不足抖动，余额保持不变。
- 场景切换和 Reality/Mirror 转换后计数器不丢失、不重复实例化。
- 精华计数器不被 ScreenFx 遮罩覆盖。
- 精华计数器锚定在屏幕右上角，与左上角生命 HUD 互不重叠。
- 精华 UI 是独立 Prefab，不随 `LevelConfig.playerHealthHudPrefab` 切换或销毁。

## 14. 推荐实施顺序

1. 将当前生命能量容量与最大生命值解耦。
2. 为敌人伤害结算暴露实际伤害结果。
3. 实现实际伤害转生命能量与小数累计。
4. 建立 `GameSessionProgress` 全局会话对象。
5. 实现生命精华查询、增加、领取去重和消费接口。
6. 为花草节点增加稳定 ID 和精华奖励配置。
7. 将花草旧的生命储备奖励改为首次领取精华。
8. 将精华规则结算与飞行特效拆分。
9. 接入精华余额 HUD（`LifeEssenceHudView`）与获得/消费反馈。
10. 将精华飞行特效对准计数器挂点，并验证规则与表现解耦。
11. 增加节点 ID 编辑器校验与验收测试。

## 15. 最终产品定义

本阶段生命资源系统最终形成两条清晰闭环：

```text
战斗闭环：
对敌人造成实际伤害
→ 获得当前生命能量
→ 消耗能量恢复生命

探索成长闭环：
首次摧毁花草
→ 精华立即进入全局会话账户
→ 本次游戏运行期间跨场景和死亡保留
→ 向后续关末成长系统提供查询与消费能力
```

生命精华属于 Demo 单次游戏会话，不写入永久存档。每个花草节点通过稳定唯一 ID 在本次会话内只发放一次奖励；重载后仍可正常打碎，但不再给予精华。游戏完全退出并重新启动后，精华余额、已领取节点和所有会话数据全部重新开始。

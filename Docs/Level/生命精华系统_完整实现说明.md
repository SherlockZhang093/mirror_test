## 2. 最终实现结论

### 2.1 已经落地的最终玩法定义

当前工程里的生命玩法已经被拆成两条闭环：

```text
战斗闭环：
玩家对敌人/Boss 造成实际伤害
→ 触发 DamageDealtEvents
→ LifeEnergyGainProcessor 按实际伤害转化生命能量
→ PlayerHealthReserve 累加当前生命能量
→ PlayerRecoveryAbility / G 恢复消耗生命能量

探索成长闭环：
玩家击碎花草/晶体/圣龛类资源节点
→ HealthResourceNode 判定耐久归零
→ GameSessionProgress 按 resourceNodeId 做本次会话唯一领取
→ 首次领取时立即入账生命精华
→ LifeEssenceHudView 右上角 HUD 同帧刷新
→ LifeEssenceTransferEffect 播放飞行表现
→ 关末成长系统消费生命精华并应用成长
```

## 3. 系统总架构

## 3.1 账户层

### `GameSessionProgress`
路径：`Assets/MirrorTrial/Scripts/Growth/GameSessionProgress.cs`

职责：
- 作为 `DontDestroyOnLoad` 的**单次游戏会话全局账户**。
- 保存：
  - `lifeEssence`
  - `claimedResourceNodeIds`
- 提供：
  - `TryClaimLifeEssence(string nodeId, int amount)`
  - `CanSpendLifeEssence(int amount)`
  - `TrySpendLifeEssence(int amount, string reasonId)`
- 实现 `IGrowthEssenceWallet`，给关末成长系统使用。
- 在游戏启动前自动 `Ensure()`。
- 在关闭 Domain Reload 的编辑器 Play 模式下，用 `SubsystemRegistration` 清理静态引用。
- 自动挂接并维持右上角生命精华 HUD。

关键实现点：
- `RuntimeInitializeOnLoadMethod(BeforeSceneLoad)`：启动即确保会话对象存在。
- `RuntimeInitializeOnLoadMethod(SubsystemRegistration)`：重置静态状态，避免编辑器残留。
- `EnsureHud()`：优先加载 `Resources/UI/LifeEssenceHudUI.prefab`；若 Prefab 丢失，则自动构建 runtime fallback HUD。
- `ResetSession()`：清空精华余额和已领取节点集合，供 New Game 调用。

### `IGrowthEssenceWallet`
路径：`Assets/MirrorTrial/Scripts/Growth/IGrowthEssenceWallet.cs`

职责：
- 把生命精华账户对外压成最小接口：
  - `Balance`
  - `BalanceChanged`
  - `TrySpend(int amount)`
- 通过 `GrowthEssenceWalletLocator` 让关末成长系统不直接依赖 `GameSessionProgress` 具体类型。

这一步的意义是：
**关末成长只知道“有一个精华钱包”，不知道钱包内部怎么存。**

## 3.2 当前生命能量层

### `PlayerHealthReserve`
路径：`Assets/MirrorTrial/Scripts/Player/PlayerHealthReserve.cs`

职责：
- 现在它不再是“花草打碎就直接加的储备”。
- 它已经被重构成**当前生命能量钱包**。

当前规则：

```text
Capacity = baseCapacity + sessionCapacityBonus + temporaryCapacityBonus
```

已落实的行为：
- 容量与 `Health.maxHP` 解耦。
- `Add(int amount)` 统一走上限裁剪。
- `TryReserveForFullHeal(out reservedAmount)` 仍服务 G 恢复。
- 回到现实层、玩家重生、某些 Reality 场景重新进入时会清空当前生命能量。
- `Awake()` 自动保证 `LifeEnergyGainProcessor` 挂在玩家身上。

### `LifeEnergyGainProcessor`
路径：`Assets/MirrorTrial/Scripts/Player/LifeEnergyGainProcessor.cs`

职责：
- 监听 `DamageDealtEvents.PlayerDamageDealt`。
- 把玩家实际造成的伤害换算成当前生命能量。

当前公式：

```text
raw = actualDamage × baseDamageConversionRate × playerConversionMultiplier + fractionalCarry
gain = Floor(raw)
fractionalCarry = raw - gain
```

当前默认值：
- `baseDamageConversionRate = 0.2`
- `playerConversionMultiplier = 1`

也就是说：
- 低伤害不会永远因为取整而白打，剩余小数会累积。
- 事件只看 `actualDamage`，过量伤害天然被过滤。

### `DamageDealtResult / DamageDealtEvents`
路径：`Assets/MirrorTrial/Scripts/Combat/DamageDealtResult.cs`

职责：
- 统一定义“玩家造成了一次真正扣血”的事件数据结构。
- 只要 `actualDamage <= 0` 或 `allowLifeEnergyGain == false`，就不会向生命能量系统抛事件。

当前接入位置（已检索确认）：
- `Assets/MirrorTrial/Scripts/Enemies/EnemyAI.cs`
- `Assets/MirrorTrial/Scripts/Boss/MirrorBossController.cs`
- `Assets/MirrorTrial/Scripts/Boss/MirrorBossActorV2.cs`
- `Assets/MirrorTrial/Scripts/Boss/MirrorBossActor.cs`
- `Assets/MirrorTrial/Scripts/Boss/MirrorArcherMountedBoss.cs`

这意味着：
**普通敌人 + 多个 Boss 实现都已经纳入“实际伤害 → 生命能量”的统一链路。**

## 3.3 资源节点层

### `HealthResourceNode`
路径：`Assets/MirrorTrial/Scripts/Resources/HealthResourceNode.cs`

这是花草/晶体/圣龛资源节点的核心脚本，当前已经完成这些变化：

#### 字段侧变化
- `healthReward` 已迁移为 `lifeEssenceReward`
- 新增 `resourceNodeId`
- 保留 `countHitsInsteadOfDamage`
- 保留受击与破碎表现配置
- 保留飞行表现配置

#### 规则侧变化
资源节点现在的摧毁逻辑是：

```text
OnDamagePayloadReceived
→ 只接受玩家来源伤害
→ 扣耐久
→ 耐久 <= 0 时调用 DestroyNode()

DestroyNode()
→ 计算 resolvedNodeId
→ 调用 GameSessionProgress.Ensure()
→ TryClaimLifeEssence(resolvedNodeId, lifeEssenceReward)
→ 成功时立即入账生命精华
→ 然后再播 LifeEssenceTransferEffect
→ 然后禁用 Hurtbox / Collider / 播放破碎反馈
```

#### 重要边界
1. **规则先结算，表现后播放**
   - 生命精华到账不依赖飞行特效。
2. **空 ID 兜底**
   - 如果场景实例还没补齐 `resourceNodeId`，会临时走：
     - 场景名 + 层级路径 + sibling index
   - 同时打印 warning。
3. **同一节点幂等**
   - `destroyed` 防止节点自身在同一次摧毁过程里多次结算。

## 8. 这轮实现中真实修过的问题

## 8.1 `ResolveNodeId` 缺失导致编译错误

问题：
- `HealthResourceNode.DestroyNode()` 中调用了 `ResolveNodeId()`
- 但函数本体当时不存在

结果：
- Unity 编译报错：
  - `The name 'ResolveNodeId' does not exist in the current context`

修复：
- 在 `HealthResourceNode` 中补上 `ResolveNodeId()`
- 逻辑：
  - 优先使用显式 `resourceNodeId`
  - 否则退回“场景名 + 层级路径 + sibling index”

## 8.2 `Object.DestroyImmediate` 命名冲突

问题：
- `LifeEssenceHudBuilder.cs` 里使用 `Object.DestroyImmediate(...)`
- 与 `object` / `UnityEngine.Object` 命名解析冲突

结果：
- Unity 编译报错：
  - `'Object' is an ambiguous reference`

修复：
- 全部改为：
  - `UnityEngine.Object.DestroyImmediate(...)`

## 8.3 外部 batchmode 无法直接处理工程

问题：
- 项目已经被另一个 Unity 实例打开
- 外部 batchmode 不能再次打开同一项目

修复思路：
- 不硬碰 batchmode
- 改成 request-file + 打开中的 Unity 自执行 builder / validator

## 8.4 节点自动补齐请求偶发不执行

问题：
- 旧逻辑只在类加载时检查一次 request 文件
- 如果 request 文件在 Unity 已运行后才生成，就可能被漏掉

修复：
- 改为 `EditorApplication.update` 持续监听
- 已实际验证：请求文件成功被消耗，场景成功保存

## 10. 当前系统边界与注意事项

## 10.1 已明确成立的边界

1. **生命精华不挂在 Player 上**
   - 玩家死亡/重建不会丢精华。
2. **生命精华不挂在单关 LevelManager 上**
   - 切场景不会丢精华。
3. **UI 只读不写**
   - 余额权威始终在 `GameSessionProgress`。
4. **飞行特效只做表现**
   - 即使特效被切场景打断，余额也正确。
5. **关末成长只依赖钱包接口**
   - 没把面板逻辑绑死在 `GameSessionProgress` 类型上。

## 10.2 当前仍值得盯的遗留点

1. **旧 Prefab 里仍可见 `healthReward` 序列化残留**
   - 当前 `HealthResourceNode` 用了 `[FormerlySerializedAs("healthReward")]`
   - 说明老资产可以继续兼容读取
   - 但 YAML 文本未必全部被重写成 `lifeEssenceReward`
   - 这不是运行时错误，但后续做资产清洁时值得统一刷新保存一次

2. **场景生成链路是否始终保留稳定 ID，还需要继续盯**
   - 现在批量补齐已经完成
   - 但如果后续重新生成关卡、复制节点、重做布局，仍要保证不会覆盖已稳定的逻辑节点 ID

3. **最终仍建议做一次完整实机验收**
   - 普通关出口
   - Mirror Boss 清场
   - 死亡重载
   - 现实/镜中切换
   - 重复打碎同一节点
   - 精华不足选卡

## 11. 推荐验收顺序

### 验收 A：花草首次领取
```text
进入 Level_Reality_01 或 Level_Reality_02
→ 打碎一个生命资源节点
→ 右上角数字立刻增加
→ 同时看到飞行特效和 +X 飘字
```

### 验收 B：重复摧毁不再发奖
```text
打碎同一个节点
→ 重载关卡
→ 再次打碎同一个节点
→ 节点仍可破碎
→ 但右上角数字不增加
→ 不播放精华获得反馈
```

### 验收 C：战斗产能
```text
攻击普通敌人 / Boss
→ 只按实际伤害增长生命能量
→ 过量伤害不多算
→ 攻击花草不产生生命能量
```

### 验收 D：关末消费
```text
清场或进入出口
→ 弹出关末成长面板
→ 余额充足时可购买
→ 余额不足时按钮不可点并提示不足
→ 购买后精华扣减，属性增长
→ 跳过时不扣钱
```

### 验收 E：会话生命周期
```text
收集精华
→ 死亡/重载/切场景
→ 精华余额仍在
→ 完全退出游戏重开
→ 精华归零
```

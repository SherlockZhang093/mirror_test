# 生命资源系统

> 关卡系统当前实现概览，整理日期：2026-07-30。本文是生命资源玩法、资源节点、Prefab 仓库和关卡编辑器接入的主文档。

## 1. 系统归属与目标

生命资源系统属于关卡玩法范畴：关卡设计者将可攻击资源布置在场景中，玩家通过攻击摧毁资源并获得可延后使用的生命储备。

核心流程：

```text
关卡放置生命资源 Prefab
→ 玩家攻击资源节点
→ 节点耐久归零
→ 固定奖励写入玩家生命储备
→ 玩家受伤后按 G 施放恢复技能
→ 技能生效点恢复生命
```

当前范围：

- 只产出生命储备，不支持货币、背包或其他资源。
- 单玩家，不处理多人归属。
- 只有玩家攻击可以伤害资源节点。
- 节点在本次关卡运行期间耗尽后不重生。
- 重新加载或重新进入关卡时，节点随场景恢复。

UI 只负责显示生命值、储备量和施法状态，详见 [生命值与生命储备 UI](../UI/生命值与生命资源系统.md)。

## 2. 模块职责

| 模块 | 职责 |
| --- | --- |
| `HealthResourceNode` | 资源节点耐久、玩家攻击过滤、受击反馈和奖励产出 |
| `HealthResourceCatalog` | 保存所有可供关卡编辑器选择的生命资源 Prefab 引用 |
| `PlayerHealthReserve` | 保存玩家生命储备、限制容量并处理清空 |
| `PlayerRecoveryAbility` | 接收恢复输入、预扣储备、施法、打断和回血结算 |
| `HealthResourceTransferEffect` | 奖励飞向玩家的纯视觉表现 |
| 生命资源编辑器 | 将美术 Prefab 配置为资源节点并注册到目录 |
| 关卡编辑器 | 从资源目录选择 Prefab，并在当前关卡放置实例 |

职责边界：

- `Health` 只管理玩家实际生命值。
- `PlayerHealthReserve` 不处理输入和动画。
- `PlayerRecoveryAbility` 不负责资源节点。
- `HealthResourceNode` 不直接控制 HUD。
- `HealthResourceCatalog` 是关卡编辑器读取生命资源 Prefab 的唯一索引来源。

## 3. 资源节点运行逻辑

### 3.1 Prefab 必备组件

生命资源 Prefab 根节点必须具有：

- `HealthResourceNode`
- `Collider2D`
- `Hurtbox`

攻击链路：

```text
玩家 Hitbox
→ Hurtbox.ReceiveHit(DamagePayload)
→ SendMessageUpwards(OnDamagePayloadReceived)
→ HealthResourceNode.OnDamagePayloadReceived
```

### 3.2 玩家攻击过滤

只有 `DamagePayload.source` 的父级中存在 `PlayerInputReader` 时，攻击才有效。

以下来源不会扣除耐久，也不会产生奖励：

- 敌人攻击。
- 环境伤害。
- 陷阱。
- 没有有效 Source 的伤害。
- Damage 小于或等于 0 的消息。

### 3.3 耐久模式

节点支持两种模式：

- `countHitsInsteadOfDamage = false`：按 `payload.damage` 扣除耐久。
- `countHitsInsteadOfDamage = true`：每次有效攻击固定扣除 1 点耐久。

公开状态与事件：

```csharp
int CurrentDurability
int MaxDurability
int HealthReward
bool IsDestroyed
event Action<int, int> DurabilityChanged
event Action Depleted
```

### 3.4 受击反馈

每次有效攻击可触发：

- Animator 的受击 Trigger。
- SpriteRenderer 材质颜色闪烁。
- 受击音效。

资源节点只扣耐久，不接收敌人式的击退、属性克制或状态效果。

### 3.5 耗尽与奖励

耐久归零后：

1. 立即把固定 `healthReward` 写入攻击者的 `PlayerHealthReserve`。
2. 找不到攻击者储备时，兜底查找场景中的玩家储备。
3. 奖励飞行动画仅负责表现，不决定奖励到账时机。
4. 禁用 `Hurtbox` 和 `Collider2D`，防止重复奖励。
5. 触发 `Depleted`。
6. 默认隐藏整个节点，不要求额外摧毁动画、粒子或音效。

超过玩家储备上限的部分直接浪费；节点仍然视为耗尽。

## 4. 玩家生命储备

组件：`PlayerHealthReserve`

公开接口：

```csharp
int Current
int Capacity
event Action<int, int> Changed
int Add(int amount)
bool TryReserveForFullHeal(out int reservedAmount)
void Clear()
```

规则：

- `Capacity` 动态等于玩家 `Health.maxHP`。
- `Add` 返回实际写入量。
- 储备不会让玩家生命值超过最大值。
- 满血时不能预扣储备。
- 储备不足时，恢复现有储备能够覆盖的生命值。

示例：最大生命 5、当前生命 2、储备 2，恢复结算后生命变为 4。

## 5. G 恢复技能

组件：`PlayerRecoveryAbility`

当前默认配置：

- 输入：`PlayerInputReader.RecoverPressed`，默认按键 G。
- 施法总时间：0.8 秒。
- 生效点：施法进度 65%。
- 可配置恢复动画 `recoveryClip`。

执行顺序：

1. 检查玩家存活、缺血、拥有储备、未重复施法且其他技能不忙。
2. 按“缺失生命”和“现有储备”的较小值预扣。
3. 锁定移动并进入 `Cast` 状态。
4. 到达生效点后调用 `Health.Heal(reservedAmount)`。
5. 动画结束后解除移动锁定和强制状态。

动画也可以通过 Animation Event 调用：

```csharp
PlayerRecoveryAbility.CommitHeal()
```

打断规则：施法被打断时，已经预扣的储备不返还，也不会回血。

## 6. 生命周期与关卡切换

- Reality 进入对应 Mirror：持久玩家携带当前生命储备。
- 返回 Reality：清空生命储备，并恢复满血。
- 玩家死亡并在当前 Reality 复活：清空储备。
- 重新进入 Reality：视为重新开始，清空储备并恢复满血。
- 进入下一现实关卡：清空储备并恢复满血。
- 资源节点耗尽状态不存档；重新加载场景后恢复。

主要依赖事件：

- `MirrorTransitionBridge.OnReturnToRealityScene`
- `PlayerDamageReceiver.PlayerRespawned`
- `SceneManager.sceneLoaded`

## 7. 生命资源 Prefab 制作

入口：

`Tools → Mirror Trial → 关卡 → 生命资源编辑器`

使用流程：

1. 选择一个美术 Prefab。
2. 设置最大耐久、固定奖励和耐久计算模式。
3. 按需要设置受击动画 Trigger、闪烁、音效和奖励飞行表现。
4. 应用配置。
5. 工具验证 `HealthResourceNode`、`Collider2D` 和 `Hurtbox`。
6. 配置成功的 Prefab 自动注册到资源目录。

当前工作流是一次选择并配置一个 Prefab，不要求多选批处理。

## 8. Prefab 仓库索引

索引资产：

`Assets/MirrorTrial/Resources/HealthResourceCatalog.asset`

`HealthResourceCatalog` 保存生命资源 Prefab 的直接引用列表。关卡编辑器只从该目录取资源，不维护第二套手工列表。

索引维护：

- 生命资源编辑器应用配置后自动 `Register(prefab)`。
- 注册时去重。
- 关卡编辑器的“刷新索引”调用 `Rebuild()`。
- 重建时扫描所有带 `HealthResourceNode` 的 Prefab，排序并去重。
- 目录为空时，关卡编辑器首次启用会自动重建。

## 9. 在关卡编辑器中放置

入口：

`Tools → 镜像试炼 → 关卡编辑器`

操作流程：

1. 打开包含 `LevelManager` 的目标关卡。
2. 切换到“玩法”页签。
3. 在“生命资源仓库”选择目标 Prefab。
4. 开启放置。
5. 在 Scene 视图左键点击一次。

生成结果：

- 创建源 Prefab 的实例并保留 Prefab 关联。
- 放入当前关卡 `GameplayRoot/HealthResources`。
- 支持 Undo。
- 放置完成后自动选中新对象。
- 每次开启放置只生成一个实例；继续放置需再次开启。

## 10. 与 UI 的接口边界

关卡资源系统只向 UI 暴露状态，不规定 UI 样式：

- `Health.Changed(currentHP, maxHP)`
- `PlayerHealthReserve.Changed(current, capacity)`
- `PlayerRecoveryAbility.CastStateChanged(isCasting)`

每个关卡通过 `LevelConfig.playerHealthHudPrefab` 决定使用哪个 HUD。HUD 的视觉规范、Prefab 层级和显示接口统一见 UI 文档。

## 12. 验收标准

- 生命资源 Prefab 能从目录出现在关卡编辑器仓库中。
- 从仓库选择后能在 Scene 视图单次放置，并保留 Prefab 关联。
- 非玩家伤害不能降低资源耐久。
- 玩家有效攻击能触发受击反馈并降低耐久。
- 耐久归零只发放一次奖励。
- 奖励立即进入玩家储备，储备不超过玩家最大生命值。
- 资源耗尽后本次关卡不重生，重新加载关卡后恢复。
- Reality 进入 Mirror 时保留储备；死亡、返回 Reality 或进入下一现实关卡时清空。
- 玩家缺血且拥有储备时，G 恢复按配置的施法时间和生效点结算。
- UI 只通过公开事件读取状态，不反向实现玩法规则。

# 生命值与生命储备 UI

> UI 设计与接口文档，整理日期：2026-07-30。生命资源的玩法规则、关卡放置和资源节点配置统一见 [生命资源系统](../Level/生命资源系统.md)。

## 1. 文档边界

本文只负责：

- 玩家生命值与生命储备的 HUD 视觉设计。
- HUD Prefab 的层级和关卡样式切换。
- UI 从运行时系统读取数据的接口。
- 受伤、低血量、死亡和恢复施法的界面反馈。

本文不定义资源节点耐久、奖励数值、G 键恢复规则、跨场景清空规则或关卡编辑器操作。

## 2. 视觉设计

### 2.1 整体结构

HUD 采用上下贴合的双条结构：

1. 上方为 5 格离散生命值。
2. 下方为一条更细、更长的生命储备条。
3. 两条在视觉上属于同一个整体，不增加粉色分隔区。
4. 储备条保持低视觉权重，不与生命值争夺注意力。

### 2.2 生命值表现

- 每一点生命对应一个独立格。
- 正常生命使用关卡对应的主色和材质风格。
- 低血量时允许切换低血量 Sprite，并进行红色呼吸提示。
- 受到伤害时，对丢失的生命格播放闪白、转红和残留淡出。
- HUD 可根据伤害量执行轻微或较强的位移抖动。
- 玩家死亡时 HUD 降低透明度；恢复生命后回到正常状态。

### 2.3 生命储备表现

- 储备条填充比例为 `current / capacity`。
- 空储备时整体降低透明度。
- 有储备时使用当前关卡的可用状态颜色。
- 施放恢复技能时切换为施法状态颜色。
- 储备条只显示数据状态，不自行决定能否恢复或消耗多少。

### 2.4 Frame 使用约束

`HealthReserve/Frame` 只允许作为可选的边线装饰：

- Frame 图片中央必须透明，不能覆盖 `Fill`。
- 如果图片不是透明中空边框，应直接禁用 Frame。
- 推荐绘制顺序为 `Empty → Fill → 可选透明 Frame`。
- 不允许用满幅不透明图片充当最上层 Frame。

## 3. Prefab 结构

建议结构：

```text
PlayerHealthBarUI_<Level>
└─ UnifiedHealthHud
   ├─ HealthSegments
   │  ├─ Life Block 1
   │  │  ├─ Empty
   │  │  ├─ Fill
   │  │  ├─ HitFlash
   │  │  └─ Frame
   │  └─ Life Block 2...5
   └─ HealthReserve
      ├─ Empty
      ├─ Fill
      └─ Frame（可选，必须透明中空）
```

`PlayerHealthBarView` 的序列化引用：

- `fills[5]`：从左到右的生命填充图。
- `hitFlashes[5]`：从左到右的受伤覆盖图。
- `normalFill` / `lowFill`：正常和低血量 Sprite。
- `reserveFill`：生命储备的 Filled Image。
- `reserveGroup`：储备区域整体透明度。
- `recoverKeyText`：可选的恢复按键提示。

## 4. 当前 HUD Prefab

| 使用范围 | Prefab |
| --- | --- |
| 默认兜底 | `Assets/MirrorTrial/Resources/UI/PlayerHealthBarUI.prefab` |
| Reality 01 | `Assets/MirrorTrial/Resources/UI/PlayerHealthBarUI_Reality01.prefab` |
| Reality 02 | `Assets/MirrorTrial/Resources/UI/PlayerHealthBarUI_Reality02.prefab` |

每个关卡通过 `LevelConfig.playerHealthHudPrefab` 指定 HUD。没有配置时才加载默认兜底版本。

运行时 HUD 会实例化到持久玩家对象下，因此切换 Reality 与 Mirror 时不会丢失；进入新关卡后，`LevelManager` 会要求现有 HUD 切换到该关卡配置的 Prefab。

## 5. 数据输入接口

### 5.1 生命值

数据源：`Platformer.Mechanics.Health`

- `CurrentHP`：当前生命值。
- `maxHP`：最大生命值。
- `Changed(currentHP, maxHP)`：生命值变化通知。

显示入口：

```csharp
PlayerHealthBarView.SetHealth(int currentHP, int maxHP)
```

### 5.2 生命储备

数据源：`PlayerHealthReserve`

- `Current`：当前储备。
- `Capacity`：储备上限。
- `Changed(current, capacity)`：储备变化通知。

显示入口：

```csharp
PlayerHealthBarView.SetReserve(int current, int capacity, bool isCasting)
```

该方法负责计算 `fillAmount`、更新储备颜色和储备区域透明度。

### 5.3 恢复施法状态

数据源：`PlayerRecoveryAbility`

- `IsCasting`：当前是否施法。
- `CastStateChanged(isCasting)`：施法状态变化通知。

UI 将 `IsCasting` 作为 `SetReserve(..., isCasting)` 的第三个参数，不在 View 中实现技能逻辑。

## 6. 运行时装载接口

`PlayerHealthBarUI` 是数据适配层：

1. 获取同一玩家上的 `Health`、`PlayerHealthReserve` 和 `PlayerRecoveryAbility`。
2. 实例化关卡指定的 `PlayerHealthBarView`。
3. 订阅生命、储备和施法状态事件。
4. 将数据转发给 `SetHealth` 与 `SetReserve`。
5. 禁用或销毁时解除订阅。

关卡切换接口：

```csharp
PlayerHealthBarUI.SetLevelViewPrefab(PlayerHealthBarView prefab)
```

`LevelManager.Awake()` 使用该接口应用 `LevelConfig.playerHealthHudPrefab`。

## 8. UI 验收标准

- 关卡运行时加载的 HUD 名称与 `LevelConfig` 配置一致。
- 当前生命值和 5 个生命格显示一致。
- 储备从 0 变为非 0 时，细条按比例增长。
- 储备减少或清空时，填充比例同步下降。
- 施法期间储备条切换到施法颜色。
- Empty、Fill 和 Frame 没有错误遮挡关系。
- Reality 01 与 Reality 02 可使用不同美术风格，但保持完全相同的数据接口。
